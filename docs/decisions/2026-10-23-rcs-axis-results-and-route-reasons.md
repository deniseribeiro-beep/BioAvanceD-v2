# 2026-10-23: the RCS assessment records each axis's resolution status and the reasons for its route

Requirement RF018 AC6, AC8 and AC9, RULE-011. Dictionary ELM-0163 (RCSAssessment.rcsAxisResults), V2E-0543 (RCSAssessment.routeReasons), V2E-0515..0523 (RCSPreanalyticalAxisInput). Issue #1320. Sequel to `2026-10-23-rcs-input-snapshot-write.md` and `2026-10-23-rcs-governance-evidence.md`.

## The question

RF018 AC6 asks that each axis preserve its observed SPREC code, severity, maximum weight, weighted penalty, mapping release, resolution status, applicable context and evidence, and AC8 that the assessment carry its gradeRoute and routeReasons. An assessment kept only `axisPenalties`, which exist only on the score route, so a governance failure recorded no per-axis status, and no assessment carried `routeReasons`. Where are both recorded, and with what values, without changing a score, grade, penalty, route, `certify` result key or `calculation_trace` (which `MerkleService.js` hashes)?

## Decided

`[inference]`, from the specification and the repo's pattern, by the coordinator for #1320, on 2026-10-23:

1. **The per-axis record is RCSAssessment's own `rcsAxisResults` (ELM-0163), with RCSPreanalyticalAxisInput's field names.** Each entry is `{ axisCode, sprecCode, severity, maximumWeight, weightedPenalty, severityMappingReleaseId, resolutionStatus, applicabilityContext, evidenceIds }` (V2E-0515..0523), with `axisCode` in the canonical `P_pre` spelling of `RcsInputSnapshot.AXIS_CODES`. They are plain objects on the assessment, not axis-input documents in the snapshot: `RcsPreanalyticalAxisInput.validate` needs a severity mapping release and evidence no source supplies, and a reference nothing backs is null or empty, never fabricated (item 2 of the snapshot-write decision). So `severityMappingReleaseId` is null and `evidenceIds` empty. `recordAssessment` writes the entries only when the input's matrix is the result's own `matrix_type`, as the AC4 resolution check beside it; otherwise, and with no `rcs_input`, `rcsAxisResults` is empty.
2. **The status is the first that holds, in the gate's own order.** For each axis of the matrix: no code is `absent`; an unknown code (`X`, `XXX`, `UNKNOWN`, `UNK`) is `unknown`; an other code (`Z`, `ZZZ`, `OTHER`) is `not_scored`, the gate's own reason being that it has no validated local interpretation, so no score rule; a code outside the SPREC pattern is `invalid`; a code outside the matrix axis's seeded catalog is `incompatible`; a catalog code whose severity mapping is unscored, null or without a seeded weight is `incompatible` when its workflow context does not match the seeded mapping and `not_scored` otherwise; anything else is `resolved`. On every scored input the five entries are `resolved` and equal `axis_penalties` item by item (code, severity, weight, penalty); on every governance failure whose trace names an axis of the matrix at least one entry is not `resolved`. A test holds both over a corpus that sets each axis to every catalog code and to unknown, other, empty, invalid and off-catalog codes, with and without a workflow rule. An input with no resolvable matrix gives no entry, since which axes apply is unknown.
3. **An unresolved axis carries null severity, penalty and context, never 0.** RULE-011 says "never assign zero" to an absent, unknown, invalid, incompatible or not_scored axis, and RF018 AC9 forbids an automatic zero (item 4 of `2026-10-22-rcs-input-snapshot-structures.md`). `maximumWeight` stays the seeded weight, which is known whatever the code. A resolved axis whose severity mapping requires a workflow context carries `{ workflowRule }` as its applicability context; any other carries null.
4. **routeReasons says what the gate found, never more.** A scored result (governance status 1, route `Score-based certification` or `Score critical penalty`, a score-based grade) gives `['no governance failure found', 'score threshold <grade>']`. It does not say V2E-0543's example "governance gate passed", because the gate never reads traceability, monitoring or documentation evidence, and `evaluateGovernanceEvidence` leaves its aggregate unresolved, never pass (`2026-10-23-rcs-governance-evidence.md`). A governance failure gives `'governance failure'` followed by its failure reasons. A result with no recognised route keeps `[]` although V2E-0543 is 1..*: no reason is fabricated, as RULE-011 keeps null rather than 0.
5. **Both are computed beside `certify`, never inside it.** `evaluateAxisResults(input)` and `routeReasons(result)` are separate methods of the certification service that `recordAssessment` calls; neither mutates its argument. So `certify`'s result, its `axis_penalties` and its `calculation_trace` are unchanged, and the Merkle hash with them; a corpus of 24673 inputs hashes `certify` to the same digest before and after.

## Not decided here

- **The severity mapping release id and the axis evidence ids**, which stay null and empty until a severity mapping release and axis evidence records exist.
- **Writing `preanalyticalAxes` into the input snapshot** as RCSPreanalyticalAxisInput documents.
- **The v2 `gradeRoute` vocabulary** (`score_based_certification`); `gradeRoute` keeps its values.
- **routeReasons for the governance criteria the gate does not read** (traceability, monitoring and documentation evidence).

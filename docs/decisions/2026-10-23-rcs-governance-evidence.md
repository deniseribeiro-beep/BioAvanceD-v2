# 2026-10-23: the RCS assessment write keeps the six governance criteria, with the rule set's version and checksum

Requirement RF018 AC7. Dictionary V2E-0524..0537 (RCSGovernanceEvidenceSnapshot), V2E-0504 (governanceEvidenceId). Issue #1320. Sequel to `2026-10-22-rcs-input-snapshot-structures.md` and `2026-10-23-rcs-input-snapshot-write.md`.

## The question

RF018 AC7 asks that an assessment keep `metadataComplete`, `terminologyValid`, `traceabilityOk`, `monitoringOk`, `documentationOk` and `semanticCompatible` individually, with references, the version and checksum of the rules and an aggregate result. The assessment kept only the aggregate `governanceStatus`, and the snapshot the write freezes carried a null `governanceEvidenceId`. Which value does each criterion take when the gate reads only some of the inputs its dictionary row names, and how is the rule set named, without changing a score, grade, penalty, route, `governanceStatus` or `calculation_trace` (which `MerkleService.js` hashes)?

## Decided

`[inference]`, from the specification and the repo's pattern, by the coordinator for #1320, on 2026-10-23:

1. **The six flags are read from the gate's own trace, re-run on the frozen input.** `rcsCertificationService.evaluateGovernanceEvidence(input)` runs `normalizeSprec`, `detectMatrixType` and `evaluateGovernance` on the snapshot's `inputs`, and `certify` once more, so the flags come from the same computation the result did (the recalculation contract of `2026-10-23-rcs-input-snapshot-write.md` item 1: `certify(readInput(p))` is `certify(p)`). One per-axis code is read too: certify's loop maps 'Analytical workflow context does not match seeded severity mapping' to SEMANTIC_INCOMPATIBILITY, so a workflow-context mismatch is a failed semantic check (V2E-0531 names "contexto"). The loop's other failures, MISSING_ANALYTICAL_WORKFLOW and NOT_SCORED, map to no flag: they are axis resolution (AC6, AC9). For those, `gateResult` stays null while the assessment's `governanceStatus` is 0.
2. **True only where the gate checked, false where it failed, null with a reason otherwise.** A flag is `true` only where the gate itself checked every input its dictionary row names, `false` where the gate failed it, and otherwise `null` with a reason in `unresolvedReasons`; never `false` for what was not checked, and never `true` from a client-sent boolean. So `metadataComplete` is always a boolean (the gate checks the matrix, sampleType, primaryContainer and the five axis codes, V2E-0526), `terminologyValid` is `true` once the matrix resolved and every present code was checked, and `traceabilityOk`, `monitoringOk`, `documentationOk` and `semanticCompatible` are `false` or `null`: V2E-0528..0531 name identification, custody, lineage, telemetry, SOPs and events, and Supplementary File 2's table asks chain-of-custody evidence for traceability and storage-condition records for monitoring, none of which this calculation reads. The pattern is RF018 AC7's "individualmente" and slice 1's item 4, where RULE-011 outranks a 1..1 rather than writing a false value.
3. **The rule-code-to-flag map.** MISSING_CRITICAL_METADATA is metadata completeness; UNKNOWN_SPREC_CODE, INVALID_SPREC_CODE and OTHER_WITHOUT_LOCAL_INTERPRETATION are terminology validity; MATRIX_INCOMPATIBLE_CODE and SEMANTIC_INCOMPATIBILITY are semantic compatibility; INSUFFICIENT_TRACEABILITY, MISSING_REQUIRED_MONITORING and INSUFFICIENT_DOCUMENTATION are their own flags. It is read off the seed's rule descriptions (`rcs-governance-rules.RCS-GOV-1.0.json`) and the Supplementary table's "Controlled terminology and context validation" row, which joins valid codes with their compatibility with matrix, event and context.
4. **`gateResult` is fail on any false flag, else null; never pass in this slice.** One g_j = 0 gives G_gov = 0 (eq:governance_product), so a false flag is `fail`, with `failureReasons` equal to the result's `governance_failure_reasons`. With no false flag, three flags are null, so the aggregate is unresolved: `gateResult` is null with its reason in `unresolvedReasons`. Every gate reason maps to one false flag, so a gate status of 0 is always `fail`.
5. **The rule set's checksum and version.** `governanceRuleSet()` hashes, as `sha256:` plus the SHA-256 of `canonicalJson` (the `ConfigurationRelease.js` checksum pattern), the model and SPREC versions, the seeded governance rules, the SPREC catalogs and the code constants the gate reads (`METADATA_AXES`, `AXES`, the unknown and other code sets, the code pattern), so a change to any rule the gate applies is a new checksum. The version is the seed's `RCS-GOV-1.0`, not rewritten to SemVer, so a captured evidence record does not pass `validate()` until a rule package names a SemVer version.
6. **`unresolvedReasons` outside `fieldsOf`, and the write order with compensation.** `RcsGovernanceEvidenceSnapshot.capture` keeps `unresolvedReasons` beside the catalog fields, as `RcsInputSnapshot.capture` keeps `inputs`, so the model keeps zero catalog drift; its `evidenceRefs` is empty, so it does not pass `validate()`. `recordAssessment` builds the evidence, the snapshot (whose `governanceEvidenceId` names the evidence, inside its hash) and the assessment before any write, then writes the snapshot, the evidence and the assessment. A failed evidence insert deletes the snapshot; a failed assessment insert deletes the evidence and the snapshot; a failed delete is logged and the insert error is the one thrown (`2026-10-23-rcs-input-snapshot-write.md` item 6). The assessment's fields do not change: it reaches the flags through `inputSnapshotId` and the snapshot's `governanceEvidenceId`.

## Not decided here

- **`evidenceRefs`**: no custody, SOP, telemetry or event record is read, so none is referenced.
- **RCSRulePackage**, and a SemVer version for the gate's rule set.
- **The axis inputs and their resolution status** (AC5, AC6, AC9), including MISSING_ANALYTICAL_WORKFLOW and NOT_SCORED.
- **routeReasons** (RF018 AC8).
- **The AC11 statement** that the RCS is not clinical validity, assay quality or a universal measure.
- **The `detectMatrixType` inference** from sample text and SPREC axes, which AC4 forbids as an unversioned rule.
- **The Foundation `rcs` readiness gate**, which stays deferred.
- **Renaming** `governanceStatus` and `governanceRuleCodes` to the catalog's `governanceGateResult` and `governanceChecks`.
